Data and privacy

Privacy Policy

Last updated September 8, 2026

This is currently a static informational website. It is not connected to your Oura account, does not request health metrics, and does not send them to AI systems.

1. The project and its operator

Personal Wellness Journal is a personal, non-commercial project maintained by the owner of the GitHub account fedak. This policy describes the current website and the planned local client for the owner's own data. Registration by other users is not currently planned.

2. Data when visiting the website

The website has no forms, advertising modules, analytics trackers, third-party fonts, or embedded content. Its code does not set cookies or use browser storage. Simply opening a page does not give the project access to Oura.

The pages are hosted on GitHub Pages. GitHub receives technical web request data and states that it logs visitors' IP addresses for security purposes. Processing and retention of this data are governed by GitHub's privacy statement. The project owner does not control the hosting logs.

3. Planned Oura integration

The integration has not yet been implemented. The planned local client will retrieve data only after the owner's explicit authorization through Oura OAuth2. The Oura password must be entered only on Oura's own website.

Depending on the permissions granted, the client may request sleep, activity, readiness, heart rate and HRV, SpO₂, stress, heart health, workout, and tag data. Profile and session data may be requested only if the corresponding features are added and the owner grants permission. The purpose is to create personal charts, comparisons across periods, and reports in Ukrainian.

4. Storage, access, and deletion

The current website has no health-data database and does not store Oura tokens. The planned first version of the client will run on the owner's computer: data retrieved for a report will be processed in memory during the session, without an automatic persistent archive. Access credentials will be stored locally with restricted access, outside the public repository and website.

The future client is intended to allow processing to be stopped by closing it and revoking access in Oura's integration settings. Local tokens will be removable. If report or history storage is added, the storage location, retention period, and deletion procedure will be described here before that feature launches.

5. Data sharing and AI

The project currently has no connected AI providers or health-data processing services. The public website does not sell or share such data. Links to GitHub and Oura lead to separate websites with their own privacy policies.

If AI-generated explanations or other external processing are added, this policy will be updated before activation to identify the provider, the data shared, the purpose, retention periods, and available privacy settings. Such sharing will require a separate, explicit decision by the owner and consideration of the applicable Oura terms.

6. Contact and policy changes

Questions about the project can be submitted through GitHub Issues. This is a public channel: do not post health metrics, passwords, or tokens. GitHub processes the content of messages under its own policy. Changes to this page will be marked with a new date; the history is available in the project's repository.
