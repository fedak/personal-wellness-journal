Data and privacy

Privacy Policy

Last updated September 8, 2026

This is currently a static informational website. It is not connected to your Oura account, does not request health metrics, and does not send them to AI systems.

1. The project and its operator

Personal Wellness Journal is a personal, non-commercial project maintained by the owner of the GitHub account fedak. This policy describes the public informational website and a separate local client for the owner's own data. Registration by other users is not currently planned.

2. Data when visiting the website

The website has no forms, advertising modules, analytics trackers, third-party fonts, or embedded content. Its code does not set cookies or use browser storage. Simply opening a page does not give the project access to Oura.

The pages are hosted on GitHub Pages. GitHub receives technical web request data and states that it logs visitors' IP addresses for security purposes. Processing and retention of this data are governed by GitHub's privacy statement. The project owner does not control the hosting logs.

3. Oura integration

The local client retrieves data after the owner's explicit authorization through Oura OAuth2. The password is entered only on Oura's own website. A service on the Mac synchronizes data approximately every 30 minutes while the computer is awake, the owner is logged in, and an internet connection is available. The initial import and a weekly recheck cover the history available through the API.

Depending on the permissions granted, the client requests all 19 supported API data types: sleep, activity, readiness, heart rate and HRV, SpO₂, stress, resilience, heart health, workouts, sessions, tags, bedtime guidance, rest mode, profile, battery levels, and ring configuration. The purpose is a personal archive, charts, comparisons across periods, and reports in Ukrainian.

4. Storage, access, and deletion

The public website has no health-data database and does not store Oura tokens. The local client stores complete API responses, retrieved records, and their observed versions in a SQLite database in the private Personal Wellness Journal folder under Library/Application Support on the owner's Mac. Synchronization updates a backup on the same Mac daily. There is no automatic expiration: data is retained until the owner deletes it. The report tables' 30-day display limit does not limit the archive.

The folder is accessible only to the owner's user account; database and credential files have restricted access permissions. Tokens are stored separately from the archive. The local report page is accessible only on this computer. The client, credentials, and data are not published in the repository or on GitHub Pages.

To stop data retrieval, the owner can stop and disable the background service or revoke access in Oura's integration settings. Closing the browser does not stop the service, and revoking access does not delete previously stored history. To delete local data, stop the service and remove the archive folder, including the database, SQLite sidecar files, and backup, as well as any exports created by the owner. Tokens and credentials can be removed separately.

5. Data sharing and AI

The project currently has no connected AI providers or health-data processing services. The public website does not sell or share such data. Links to GitHub and Oura lead to separate websites with their own privacy policies.

If AI-generated explanations or other external processing are added, this policy will be updated before activation to identify the provider, the data shared, the purpose, retention periods, and available privacy settings. Such sharing will require a separate, explicit decision by the owner and consideration of the applicable Oura terms.

6. Contact and policy changes

Questions about the project can be submitted through GitHub Issues. This is a public channel: do not post health metrics, passwords, or tokens. GitHub processes the content of messages under its own policy. Changes to this page will be marked with a new date; the history is available in the project's repository.
