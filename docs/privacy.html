1. Проєкт і відповідальна особа

Personal Wellness Journal — персональний некомерційний проєкт, який підтримує власник GitHub-акаунта fedak. Ця політика описує публічний інформаційний сайт та окремий локальний клієнт для власних даних його власника. Реєстрація інших користувачів наразі не передбачена.

2. Дані під час відвідування сайту

Сайт не містить форм, рекламних модулів, аналітичних трекерів, сторонніх шрифтів або вбудованого вмісту. Код сайту не встановлює cookies і не використовує сховище браузера. Просто відкривши сторінку, ви не надаєте проєкту доступу до Oura.

Сторінки розміщені на GitHub Pages. GitHub отримує технічні дані вебзапитів і повідомляє, що реєструє IP-адреси відвідувачів для безпеки. Обробка цих даних і строки їх зберігання регулюються політикою конфіденційності GitHub. Власник проєкту не керує журналами хостингу.

3. Інтеграція з Oura

Локальний клієнт отримує дані після явної авторизації власника через OAuth2 Oura. Пароль вводиться лише на сторінці Oura. Служба на Mac синхронізує дані приблизно кожні 30 хвилин, поки комп’ютер не спить, власник увійшов у систему та є доступ до інтернету. Початкове завантаження й щотижнева повторна перевірка охоплюють доступну через API історію.

Залежно від дозволів клієнт запитує всі 19 підтримуваних типів даних API: показники сну, активності, готовності, пульсу та HRV, SpO₂, стресу, стійкості, здоров’я серця, тренування, сесії, теги, рекомендації часу сну, режим відпочинку, профіль, заряд і конфігурацію кільця. Мета — особистий архів, графіки, порівняння періодів і звіти українською.

4. Зберігання, доступ і видалення

Публічний сайт не має бази показників здоров’я й не зберігає токени Oura. Локальний клієнт зберігає повні відповіді API, отримані записи та їхні спостережені версії в базі SQLite у приватній папці Personal Wellness Journal всередині Library/Application Support на Mac власника. Щодня під час синхронізації оновлюється резервна копія на тому самому Mac. Дані не видаляються автоматично: вони зберігаються до видалення власником. Обмеження таблиць звіту останніми 30 днями не обмежує архів.

Папка доступна лише обліковому запису власника; файли бази й облікових даних мають обмежені права доступу. Токени зберігаються окремо від архіву. Локальна сторінка звіту доступна лише на цьому комп’ютері. Клієнт, секрети та дані не публікуються в репозиторії або на GitHub Pages.

Щоб припинити отримання даних, власник може зупинити й вимкнути фонову службу або відкликати доступ у налаштуваннях інтеграцій Oura. Закриття браузера не зупиняє службу, а відкликання доступу не видаляє вже збережену історію. Для видалення локальних даних потрібно зупинити службу, видалити папку архіву разом із базою, допоміжними файлами SQLite й резервною копією, а також будь-які створені власником експорти. Токени й облікові дані можна видалити окремо.

Зараз у проєкті немає підключених ШІ-провайдерів або сервісів обробки показників здоров’я. Публічний сайт не продає та не передає такі дані. Посилання на GitHub і Oura ведуть на окремі сайти з власними правилами конфіденційності.

Якщо буде додано пояснення за допомогою ШІ або іншу зовнішню обробку, перед її ввімкненням політика буде оновлена: із зазначенням провайдера, набору переданих даних, мети, строків зберігання та доступних налаштувань приватності. Таке передавання потребуватиме окремого явного рішення власника та врахування застосовних умов Oura.

Питання щодо проєкту можна залишити в GitHub Issues. Це публічний канал: не публікуйте там показники здоров’я, паролі або токени. Сам текст звернення обробляє GitHub за власною політикою. Зміни цієї сторінки позначатимуться новою датою; історія доступна в репозиторії проєкту.
